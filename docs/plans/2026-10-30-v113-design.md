# v1.0.13 正确性修复设计

用户已在 v1.0.12 审查后明确要求修复 8 项、补齐真实入口回归、推送并发布 v1.0.13。采用审查报告的最小修复路线，不等待重复确认。

## 范围与取舍

- 保留原生 MV3、PDF.js 与现有读写流程。相对于只改文案，修正可复现行为；相对于大规模重构，仅改出错路径。
- PDF 按页路径移除虚构页码的全文兜底；无可提取文本明确失败，不自动更换协议/模型。失败页不因 DOM 重绘自动重试，由用户明确重试，避免永久错误循环（网络单请求已有有限重试）。
- 输入请求绑定目标与编辑代次，继续输入、composition、移除或清空使旧响应失效；富文本仅替换自身区域且不抢回其他目标焦点。
- 已译网页跟踪干净原文签名，合并 characterData/childList 变化。忽略扩展自己注入的译文；源文变化时清理旧结果、隔离迟到响应并重新观察。
- HTML 按 DOM 顺序提取正文文本，容器/表格/嵌套块不遗漏不重复，代码原样保留，排除非正文和隐藏内容。没有可提取正文时明确失败。
- 非 PDF 图块按新配置重译图注和已有原文标签，然后用原图重绘；标签失败保留明确未完成状态，支持续译与恢复上一版。
- HTML 导出沿用工作台的核心双栏、跨栏与图文规则，不引入另一套 Grid 排序。
- 所有运行界面和当前能力说明收敛“无痕/精确还原/任意输入框”等承诺；历史更新记录保留。

## 验收与发布

每项缺陷先用上一轮合成夹具证明旧行为，再增加正确行为断言。Node 负责状态边界；真实 Chromium 负责上传、键盘、设置变更、请求次数、下载及重开成品。全套 verify/browser/pack 通过，ZIP 精确文件与 CRC/摘要验证，解压加载入口通过；推送 main 和 annotated v1.0.13，GitHub CI 通过后发布含 ZIP、SHA256 和中文说明的 Release。

不包含另列的长 PDF 右栏分层、大图预算、字幕时间索引及 SRT 工具统一。测试不用用户密钥，不调用付费模型，不宣称覆盖所有线上 YouTube/富文本编辑器。
