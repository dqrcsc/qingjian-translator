# v1.0.5 lifecycle and accounting fixes

The user approved implementing the October 22 review findings and publishing v1.0.5. Keep MV3, classic content scripts, existing request scopes and all-or-nothing batch results. No additional runtime dependency.

Chosen design: resolve protocol from raw settings before defaults, using one classic-script helper also imported by ES modules. When scanning a paragraph for a new session, retire its old cleanup marker before observation. Give image operations an identity stored in a WeakMap, preserve the scope's AbortSignal through image decoding, and verify ownership before any post-await UI commit. Count successful paragraphs and source characters only at the outer batch boundary; retain request accounting and separately count subset retry batches. Historical totals cannot be reliably reconstructed.

Alternatives: disabling asynchronous cleanup would cause long synchronous DOM work on large pages; rewriting all UI state into a framework adds unrelated migration risk. Keep bounded frame cleanup and repair ownership at the boundary instead.
