## 性能观察与取舍

最终全量本机样例的“上传、首译两页、跳到末页”耗时分别约 3.25/3.00/2.50 秒，三个规模的右侧挂载均为 8 页。这是本地模拟 HTTP 与合成 PDF 的观察，不是服务商性能基准，不据此宣称随页数线性提速或总内存恒定。

采用显式分组阅读而非可变高度连续滚动虚拟化，降低定位、搜索、导出恢复的复杂度；已处理块、原 PDF 与图像数据仍随文档增长。对超长文件不承诺恒定总内存。

最终全量曾复现快速远页跳转后立即翻译报“PDF 取页任务仍在结束”：旧预览取消后 worker lease 尚未释放，新任务被拒绝。改为有界、可取消的等待交接，仍不超过原取页/后台任务上限；新增确定性迟到取页交接测试，原永久挂起保护测试仍验证无新增 worker 任务且等待可取消。此问题修复后重跑全量，不靠增加该场景等待绕过。

第二轮全量进一步复现补全打印停在第 3 页：PDF.js 的生产端已关闭并删除流，而迟到的取消消息未收到确认，文本取消承诺永久等待并占用槽位。对两份打包 MessageHandler 做最小补丁，已关闭的流也回复取消成功；两个测试直接执行打包代码，确定性控制 CLOSE/CANCEL 顺序，修复前均失败，修复后均通过。保留原始及修改后 SHA-256、可重放补丁和逆向校验，不放弃资源上限或取消保护。

额外修复页码回车后失焦重复重建 DOM 吞掉紧接着按钮点击的交互，由“跳第 9 页后立即点单页翻译”的实际流程覆盖。
