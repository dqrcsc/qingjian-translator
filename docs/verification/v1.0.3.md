## PDF 实际渲染

`tests/pdf-fixture.mjs` 生成不包含第三方内容的两页 PDF：标准 Helvetica 字体、两列文本、旋转页、矢量色块，以及自制的 2×2 无损 JPEG2000 图像（执行 OpenJPEG 解码路径）。

- 真实本地模块 worker 启动；没有回退到主线程 fake worker。
- 第一页为 300×400，旋转后第二页为 400×300。
- 提取到 `Left column Right column`，文字坐标为有限值且宽度大于 0。
- 第一页 12,104 个非白像素，确认文字、矢量色块与 JPEG2000 图像实际输出；已查看生成的截图。
- 原始 1,431 字节输入缓冲区保留，没有被转移给 worker 后失效。
- 已取消的加载请求被拒绝；加载过程中取消也能终止加载并释放 worker。

## 端到端取消

Node 测试通过真实前后台传输适配器、模拟 runtime Port 与 HTTP fetch 验证了队列、响应体、重试等待和图像下载；也覆盖 Gemini 与 OpenAI 两条协议路径。

浏览器测试另启动只监听 `127.0.0.1` 的 HTTP 服务，先返回响应头和未完成的 JSON 响应体：

1. 在工作台启动 PDF 翻译，触发真实“暂停翻译”按钮事件。服务端观察到连接关闭；同组第二页及额外已取消的排队任务均未发送。
2. 取消后发起新任务，可以成功获取译文，且不命中取消任务的缓存。
3. 恢复翻译后切换到 Markdown 文档，旧连接关闭，新文档正常加载。
4. 关闭扩展页面，浏览器断开该页面的 Port，后台中止它的网络请求。
5. 打开实际弹窗页面并点击快速翻译，关闭弹窗后本地服务端观察到该请求连接关闭。弹窗与后台向旧标签页补注入时，均先加载请求模块，再加载内容脚本。

实机测试曾复现“取消第一个请求释放槽位，第二个请求先于其取消事件启动”的问题。最终实现先移除整组队列项，再中止运行请求，浏览器回归现已覆盖此顺序。其他作用域的请求不受影响。

## 复现

```sh
npm ci --ignore-scripts
npm run pack
npx playwright install chromium
npm run test:browser
```

浏览器报告、PDF 样例和截图写入忽略提交的 `dist/browser-verification/`。CI 安装锁定版本 Playwright 对应的 Chromium 后运行相同脚本。可用 `CHROMIUM_EXECUTABLE` 指定其他 Chromium 做兼容性补测。

这份记录证明上述样例和取消行为，不能替代所有字体、表单、加密文件、浏览器及模型组合的兼容认证。HTTP 连接中止也不保证模型服务商停止内部计算或退回已计费用。
