# 青简 · 译读 (QingJian) v1.0.17 发布说明

发布日期：2026-10-31

本版针对 `v1.0.16` 解决 30 秒连接断开（`请求连接已关闭`）后暴露出的 **高密度学术 PDF 单页翻译在 90 秒处触发 `请求已超过总时间预算（90 秒）`** 问题进行了根因修复与单页并发加速。

## 1. 超时预算对齐与禁止超时重跑

- **根因**：此前 `callOpenAiCompatibleApi` 对文本批次请求使用默认 `45000ms`（45 秒）单次尝试超时，且 `fetchWithTimeoutAndRetry` 在单次尝试被 45 秒定时器中止后，因外层 90 秒总时间预算尚未到期（`!callerSignal.aborted`），会吞掉超时异常并从头发起第 2 次完整重试；第 2 次重试运行约 44.4 秒后必然在 90.0 秒整撞上外层 `createRequestBudget` 总预算，报错 `请求已超过总时间预算（90 秒），已停止排队和重试，请重试或在设置中调整预算。`
- **修复**：
  - 将 OpenAI 兼容接口与 Gemini 原生接口的单次请求超时统一对齐到用户配置的 `requestBudgetSeconds`（默认 90 秒，最低不小于 85 秒），让慢速推理模型单次请求可使用完整时间预算。
  - 在 `fetchWithTimeoutAndRetry` 中区分「单次尝试超时」与「临时网络异常」，当单次尝试因自身超时定时器中止时立即抛出超时错误，不再盲目重跑第 2 次完整请求。
  - 为 Gemini `2.5-pro` 等思考模型补充 `thinkingConfig: { thinkingBudget: 128 }`（若网关不支持则自动回退），避免无限思考耗尽单页时间预算。

## 2. 原生矢量文本 PDF 并发小批次加速

- **优先复用本地 PDF.js 2D 版面段落提取**：对于包含丰富原生矢量文本层的电子版学术 PDF（如 arXiv LaTeX 论文），无论配置 OpenAI 兼容协议还是 Gemini 协议，均直接复用本地毫秒级 `extractStructuredPdfPageBlocks` 2D 坐标聚类段落，仅在扫描件或缺少矢量文本层的页面上调用整页多模态图片识别（`ANALYZE_PDF_MULTIMODAL`），避免让模型在 JSON 中重复回传整页数千字符的英文原文。
- **单页并发小批次翻译**：将单页 PDF 的结构化段落按小批次（每批最多 3 段、900 字符）切分，并通过 `Promise.all` 并发提交后台并发池（受 `maxConcurrency` 控制），将原先单页整包 2300+ 字符的串行长请求拆解为多个 12~20 秒即可返回的小批次并发请求。

## 3. 验证与打包

- 新增单次超时不重跑与 PDF 单页并发小批次单元测试，通过 `npm run verify`（47 项结构校验 + 216 项单元测试全部通过）及 `npm run pack` 发布包校验。
